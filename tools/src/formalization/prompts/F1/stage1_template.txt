=== OUTPUT: the plan JSON (write to the plan path given in the brief) ===

The file must be valid JSON: after writing it, read it back and check it (balanced brackets and braces, no trailing comma, every string closed) before returning; the runner parses it and sends a file that does not parse back to you once.

`"env"`: an array of S-block entries — the ambient world(s) the result lives in (PO system / SCM / panel DGP / probability-measure space / overlap regime). Each binds a subset of symbols + (optionally) the sampling model to a chosen library world; it is DERIVED from the core's symbols + sampling_model. Picking the wrong world (a PO-system result without the PO system) is an infidelity, and the world is the single highest-leverage reuse decision. Fields: `{id:"S1", world, binds_symbols:[…], binds_sampling_model:bool, disposition:"reuse"|"define-local", reuse:<decl or null>, modules:[…], notes}`. EVERY core symbol must be bound by some S-block. `world` is READER-FACING and published verbatim in the paper: only the self-contained mathematical setting, math in `\(…\)`; every process artefact (round logs, search traces, reuse rationale, encoding instructions, decl / file:line pointers) goes in `notes`.

`"nodes"`: an object keyed by core node id — EXACTLY ONE entry per node in `coreNodeIds`. Each: `{lean_kind, lean_name, disposition:"reuse"|"define-local", reuse:<decl or null>, modules:[…], defer_tier:bool, gate:bool, …kind-specific…}`.

Node → Lean mapping (one-to-one; the `lean_kind` enum is exactly `assumption|structure|def|theorem|lemma`):
- assumption atom → `lean_kind:"assumption"` — ONE named `def … : Prop`. Whether it is used inline (a statement lists it in `hyps`) or bundled (a class lists it in `members`) — or both — is captured by those references; a shared atom is still one `def`.
- definition, CLASS (`by_member_properties` present) → `lean_kind:"structure"` + `members` == the core's `by_member_properties` (one field per member, typed by that member's Prop def).
- definition, CONSTRUCTION (`inputs` present) → `lean_kind:"def"`.
- statement (any id prefix, including `prop:`) → `lean_kind:"theorem"` (T-block) or `"lemma"` (L-block) + `target_file`, `hyps`, and `local_id` (paper-scoped).
- statement, CITED GATE (`gate:true`, `gate_class:"cited"`: a core `status:"cited"` statement with `source.carrier:"logical-claim"`, left cited) → `lean_kind:"assumption"`: a named Prop def threaded as a hypothesis into consumers, not a proof obligation. The cited bibliographic-metadata exception is specified below and maps to a non-Prop `def` instead. A cited statement with `cited_in` is a published result that the proof of the result named there (the host) invokes: its text is a passage of that proof, and its proposition is ONLY what the passage attributes to the cited result — the assertion the citation is attached to — stated in the host's context (its objects and standing hypotheses). Whatever else the passage asserts is the host's to prove and is never part of this proposition.
- Every `define-local` or gated statement carries `reuse_class`: `"standard"` (a standard, named or textbook result, even if the paper re-proves it), `"general"` (a lemma stated over base-library/toolkit vocabulary that would be reused outside this paper) or `"paper-specific"` (stated over this paper's own objects). It is a classification only; it changes nothing else.
- Every node is delivered: omit `delivery_status` (it defaults to `"deliver"`) and `delivery_role`. Only a `gate_class:"cited"` node no delivered statement depends on may be `delivery_status:"undelivered"`, with a `delivery_reason` (it then gets no Lean declaration); the gate (P10) refuses it on anything else.
- A statement's `hyps` ⊆ its core `depends_on`; each hyp is an assumption id OR a class id (constructions and lemmas are USED, not assumed). Every assumption in `depends_on` the statement holds UNDER surfaces directly in `hyps` or via a bundled class listed there (one it only names inside its conclusion does not); the gate does not check this coverage — the F2.5 review of the Lean statement against the paper's does.
- `notes` (a node's or an S-block's) state the CURRENT plan of that entry only — its search trace, the statement shape F2 must realize, the reference F3 adapts — in at most 2000 characters. The plan is not a log: it never records an earlier revision, what a change superseded, or a removed node. Write no key the plan schema does not define, in an entry or at the top level.
- `target_file`: a single statement → `Basic.lean`; ≥2 statements → one `T<id>.lean` per theorem + `Basic.lean` for shared defs/structures/L-lemmas. Plan the layout from the START under the HEADER CONTRACT above: group self-contained clusters; size for projected post-proof length (target ≤600 lines, split before ~900 only for an independent topic/proof chain); split a shared L-cluster by subsystem into `Helpers/<Topic>.lean` files in a dependency chain. F2 may refine the split.

=== REUSE → BUILD-INLINE → DEFER (per node; the heart of the plan) ===

**Step 0 (reuse), for EVERY node — including the `small` ones.** Confront the node's LIBRARY REUSE CANDIDATES, then survey the libraries yourself. You have no shell here (your tools: Read, Grep, Glob and the lean-lsp searches): take the library SOURCE PATHS from the LIBRARY SEARCH block — its commands are the later stages' — Grep them for the concept words, Glob for the topical file, THEN read that source. `lean_local_search` is a flaky backup; `lean_loogle`/`lean_leansearch` index MATHLIB ONLY. A `small` routine lemma (a KL/variance/tail bound, a measurability/integrability fact, an algebraic identity) is exactly what the library most often ALREADY provides — "small" is a reason to suspect reuse, not a licence to rebuild. A factored piece often holds under weaker hypotheses than a module's headline theorem. NEVER conclude absence from a weak scan or a wrong-base `ls` (library sources live at the paths the LIBRARY SEARCH block names, not under the cwd — empty ≠ absent). If a fit exists at the right abstraction → `disposition:"reuse"`, `reuse:"<fully-qualified decl>"` (prefer a base-library or toolkit decl over rebuilding from Mathlib); verify its signature with `lean_hover_info` first.

**Analogous-module search.** For a node with no exact match — or a genuinely hard proof step — do a SECOND pass for an ANALOGOUS decl/module carrying the SAME proof pattern (the same remainder identity for a sibling object; the same wrapper for a neighbouring rate), grepping by TECHNIQUE words. Record it (`file:lemma`) in `notes` as the reference F3 should adapt, with the gap to bridge. A piece whose technique exists elsewhere is build-inline, not Defer.

**Search trace (prove-you-searched).** Every `define-local` node AND every `defer_tier:true` node carries a one-line re-runnable search trace in `notes` — the literal concept words grepped + the modules scanned + the result. The library sources do NOT include Mathlib, so for a plausibly-standard fact (measure theory / analysis / probability / algebra) the trace must ALSO record a Mathlib-side check (`lean_leansearch`/`lean_loogle`). An absence asserted without such a trace is treated as un-searched and bounced.

**Then triage define-local:**
- The substrate-gate assumption/threading rule below is for logical gates only. A frozen cited `bibliographic-metadata` node follows its explicit non-logical exception and is never threaded.
- **Build-inline** (`defer_tier:false`): a node the core INTRODUCES that an in-scope statement is stated over (a class structure, a construction), OR a `small` (≤1 file, routine) lemma — F2 scaffolds, F3 proves, IN SCOPE. A node whose only missing pieces are build-inline stays in scope.
- **Defer** (`defer_tier:true`): ONLY a statement the core marks `status:"cited"` — a classical, named, externally-established fact, not this paper's — that you leave cited; the gate (P8) refuses `gate:true` on any other statement, and `defer_tier:true` on a `define-local` node that is not such a gate. Every such node is a **substrate-gate**: set `gate:true` and disclose it as substrate debt until discharged. A delivered paper-owned `proved`/`to-prove` statement or supporting node MUST remain `defer_tier:false, gate:false` regardless of difficulty so F2 scaffolds it and F2.5–F4 attempt and review its proof. Never omit or assume a paper contribution at F1; proof failure is handled downstream. Tag by BUILDABILITY: an external fact genuinely INFEASIBLE to formalize here (a major upstream Mathlib contribution, e.g. a general decision procedure) is a gate even when it is the engine of a theorem. Mis-tagging novel content as a gate is laundering.
  A substrate-gate MUST be a `lem:`/`thm:`/`prop:` node of core `status:"cited"` with `gate:true` and `lean_kind:"assumption"`; thread it into EVERY consumer's `hyps` (the consumer is conditional on it). **External provenance, `gate_class`, and cited carrier kind are fixed before F1 — never manufacture them from proof difficulty.** A `status:"cited"` statement is planned one of two ways. PROVED — when a base-library or toolkit theorem gives it directly or by a short bridge: `lean_kind:"lemma"|"theorem"`, `disposition:"define-local"`, `gate:false`, no `gate_class`, `citation_discharged:true`, its `source` kept; it is scaffolded and proved like any result, and its consumers need not list it in `hyps`. LEFT CITED — otherwise: `gate:true, gate_class:"cited"`. Either way: mint a `citations[]` entry `{id:"cite:<slug>", title, authors (one string), year (integer), locator, and arxiv | doi | url when the bibliography gives one}` from its `source.{cite,locator}` + `bibliography`, set the node's `source` to that id (a string), and map the frozen `source.carrier` exactly. `source.carrier:"logical-claim"` MUST be `lean_kind:"assumption"`, encoded as a named Prop and threaded into every logical consumer. Only `source.carrier:"bibliographic-metadata"` may be `lean_kind:"def"` with a closed non-Prop payload that records the source-supported scope/provenance/delivery clauses exactly; it is NEVER threaded into `hyps`, used as a proof premise, or supplemented with a Prop merely to satisfy review. The core classifies every mathematical claim (bound, rate, equality, causal/quantitative assertion, existence, or other truth-valued fact) as `logical-claim`; the plan cannot relabel one as metadata. The supported citation-discharge path may later replace a logical cited gate with an exact proved `lemma`/`theorem`; in that case retain `source`, remove the gate keys and consumer `hyps`, and re-review every consumer (that path stamps `citation_discharged:true`, the PROVED form above). Do not turn an unproved citation into a non-gate assumption or crux. A genuinely published, exactly source-matched result outside this paper's contribution may remain cited even when a delivered headline invokes it (for example, a prior lower bound matching this paper's new upper bound). Every paper-owned/new adaptation, embedding, normalization or experiment transfer, regime splice, and theorem step MUST be formalized; proof difficulty never makes it cited. Never reconstruct a still-deferred cited node as sub-lemmas. A `status:"proved"/"to-prove"` statement is paper-owned proof work: `reuse` if the library has it, otherwise keep it `defer_tier:false, gate:false` for F2–F4. It may not become planner-authored `gate_class:"gated"` debt.
  For cited logical claims, F2 emits the proposition universe using unshadowable `Sort 0` syntax (semantically `Prop`), never a shadowable `Prop` identifier. For cited metadata, “closed non-Prop payload” means a direct literal `_root_.String`, `_root_.List _root_.String`, or `_root_.Array _root_.String` result. Never use unqualified carrier names, `Sort`, `Prop`, a type alias, or a helper-defined payload.
  **Gate-consumer rule:** a statement whose difficulty is due to a frozen external gate is itself IN-SCOPE — `defer_tier:false`, thread the gate into its `hyps`, PROVE it conditional on the gate. Never defer a consumer for its own ungated content.

- **NO TAUTOLOGICAL CONJUNCTS.** When a claim's substance rests on an object the plan cannot formalize (an external result's validity "under its own hypotheses", an informal notion of a separately valid bound), do NOT keep its logical shell as a theorem conjunct — a model-independent conjunct ("if u ≤ A and u ≤ B then u ≤ min{A,B}") propagates into published nonsense. Route it through a cited-dependency interface when one exists, otherwise leave it out of the formal statement and record it in `notes` as presentation-only narrative.

**CLASSIFY EVERY ASSUMPTION, then route substrate FACTS — never silently assume a theorem.** For each `assumption` node (record the class, one phrase, in its `classification`):
  - **Modeling assumption** — a restriction on the data law / design / policy class / estimator quality (margin, overlap-decay, unconfoundedness, positivity, nuisance-rate, bounded-outcome): keep it as an `assumption`; never "built".
  - **Substrate fact** — a GENERAL mathematical theorem that happens to be hard (a concentration bound, an information inequality, an orthogonality identity). RESPECT THE AUTHOR'S ATOMIZATION: the note stating it as its OWN `ass:` node is a deliberate modeling boundary. DEFAULT: keep it a threaded Prop hypothesis. Reclassify ONLY in one clean case: (1) a base library or the toolkit PROVES the EXACT condition (a decl whose CONCLUSION type-matches the atom IN FULL — no population-vs-empirical / norm / regime mismatch, no un-built bridge) ⇒ DISCHARGE: `lean_kind:"lemma"`, `disposition:"reuse"`, `reuse:"<decl>"`, and REMOVE it from every consumer's `hyps`. A PARTIAL fit is NOT a discharge — discharging it is precisely what makes F3 later escalate a FALSE `needs-substrate` on the unprovable bridge. (2) Otherwise KEEP it threaded; do NOT escalate an `ass:` node as missing-substrate (the author declared it an assumption) — a full discharge is optional non-blocking upstream debt (record in `notes`).
  Discriminate by the NOTE'S node kind: `ass:` ⇒ threaded hypothesis (discharge only on a clean total fit); `lem:`/`thm:`/`prop:` ⇒ derive-or-reuse, never silently assume. The silent-gate defect is recording a `lem:`/`thm:`/`prop:` PROOF-OBLIGATION, or a silent ambient prerequisite you would otherwise add un-declared, as an ordinary assumption — such a node is build work (`define-local`, `gate:false`, proved in F2–F4) — or, only when the core marks it `cited`, a cited gate threaded as above; the opposite error — discharging or escalating a declared `ass:` — over-formalizes the paper and triggers false missing-substrate halts.
