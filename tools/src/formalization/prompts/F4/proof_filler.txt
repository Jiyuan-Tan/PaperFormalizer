=== SOURCES — READ BEFORE PROVING ===
The spec of record is the typed `core.json`: the user's paper as its referee accepted it — the corrected
statements plus the conditions and readings pinned on them (binding). You verify that paper; you never

formalized — no plan entry, no declaration, no `@node` tag: it only says that the statements split off

A node's PROOF ROADMAP is the human proof; for a repaired result it opens with

step before filling a sorry; do not invent a strategy the roadmap does not take. Open a Lean file to
edit it, to read the declaration you are proving, or to unfold a definition it uses — not to re-read
what this page already quotes.

=== FROZEN STATEMENTS — EDIT TO MATCH THE NL; F2.5 RE-GATES EVERY CHANGE ===
A `[FROZEN STATEMENT]` node is a paper theorem carrying its NL statement. You MAY edit its Lean statement
(add a missing premise, fix an under-specification, correct the encoding) WHENEVER the edit makes the
Lean MORE FAITHFULLY realize the NL. Disclose every edit (an added premise in `added_assumptions[]`
with its `classification`; a re-encoding in `summary`). F2.5 re-reviews every changed frozen statement
against its NL, so do NOT escalate a faithful-to-NL fix — just make it.

THE ONE HARD RULE — direction of truth: change the statement only TOWARD the NL, NEVER AWAY from it to
make a proof go through. Dropping a term, weakening a bound/rate, flipping ∀→∃, or strengthening a
hypothesis until the claim trivializes is gerrymandering — rejected as drift, round wasted. Match the
NL exactly: add what it implies (a well-posedness `Integrable`, a named condition's documented domain),
encode what it states — no more, no less.
A VERSION YOU CHOOSE for an object defined up to null sets (`Classical.choose` of an a.e. identity: a
conditional expectation, regression, density) carries `Measurable`; without it the chosen function's
sections and off-support values are arbitrary and a fiberwise claim about it can be false.
MEASURABILITY/BOUNDEDNESS of construction-provided objects: when a proof needs a plug-in / estimator /
nuisance / test function to be `Measurable` (or bounded / integrable) and the core's construction
provides it as such (built from measurable maps, drawn from a bounded class), DERIVE it from the
construction; add it as a `regularity-bookkeeping` premise only when the construction plainly entails it
and deriving it is impractical. It is NOT `needs-substrate` and NOT `ambiguous-spec`.

ESCALATE only when editing-the-Lean-to-match-the-NL is NOT the fix; do not thrash. If a PRIOR FILLER
SESSIONS block shows an earlier session already stopped at the blocker you are about to leave unchanged,
do not return another no-change round — close something else, or escalate it now:
- `statement-wrong` — the paper's claim ITSELF is wrong, vacuous, or inconsistent, or it needs a
  condition the paper neither states nor entails (the Lean already faithfully realizes it; the defect is
  upstream). The orchestrator rules on it as a proposed rewind: approved, the paper's referee repairs
  the statement.
- `needs-substrate` — a primitive you cannot build is missing (search first, per below).
- `ambiguous-spec` — the NL is genuinely ambiguous about the intended object AND no pinned reading or
  standard convention settles it (objects defined up to null sets are read a.e. / "some version has the
  property"; a referee-written condition means what the result's proof uses it for).

NEVER cheat-close a content goal with bare automation. A frozen theorem's crux (rate / bound /
separation / existence) must be discharged by a proof that genuinely invokes its supporting lemmas and
constructions — NOT a lone `tauto` / `trivial` / `simp_all` / `omega` / `decide` / `exact?`. Such a
tactic closes a crux only when the goal is degenerate or the hypotheses are CONTRADICTORY, silently
laundering a false result past the build. If you cannot write the genuine assembly, leave `sorry`.

NEVER turn a declaration into an `axiom` (nor use `admit`, `opaque`, `@[implemented_by]`)
to make a `sorry` go away: `axiom foo : P` ASSERTS `P` unproven, deletes the
warning, and evades the sorry-scan. `sorry` is the ONLY permitted placeholder; the declaration KIND and
its `:=`-body shape are FROZEN (`theorem … := by sorry`). An unfinished goal stays a VISIBLE `sorry`
(with `-- BLOCKER: needs-substrate(<primitive>)` + escalate when it needs substrate). A run ending with
any research-file `axiom` is a FAILED fill.

=== ADDING ASSUMPTIONS ===
You MAY add a hypothesis only when it is faithful to the paper or regularity bookkeeping as defined
here. Add it to the Lean AND disclose it in `added_assumptions[]`, classified:
- `faithful-refinement` — the paper states/implies it (cite where in `anchor`).
- `regularity-bookkeeping` — a measurability / integrability / finiteness side-condition the paper's
  setup entails or its own expression presupposes (an integral it writes must exist). Derive it inline
  if FREE (a bounded measurable function on a probability measure is integrable); name it as a premise
  only if not free. Weak-overlap carve-out: integrability of an unbounded inverse-weight/score is
  DERIVED from the tail/overlap assumption, never a free standalone premise. A condition a step needs
  that the paper neither states nor entails is NOT bookkeeping: it is a gap in the paper — leave the
  step `sorry` and escalate `statement-wrong` naming the condition (the referee adds it to the paper's
  statement and reports it).
  NOT bookkeeping: a structure the paper never assumes that only a library lemma wants (a standard
  Borel ambient space for a kernel or CondIndepFun lemma, …). Prove the step without it (event
  factorization extended by approximation, Fubini on the product space); if you cannot, leave the
  step `sorry` and escalate — never add the instance.
- `substrate-gate` — a genuinely CLASSICAL, named, dischargeable fact (concentration bound,
  disintegration identity, empirical-process bound) that is NOT the crux; allowed only as VISIBLE
  debt: the result is then reported as conditional on it, never as proved outright.

NEVER assume the CRUX. A rate / bound / separation / identity the paper DERIVES is CONTENT, not a gate —
assuming it is laundering. When honest closure needs substrate you cannot build here, leave
`sorry -- BLOCKER: needs-substrate(<primitive>)` and ESCALATE `needs-substrate` rather than assuming it.

SEARCH BEFORE you escalate `needs-substrate` — a false "it's missing" wastes a build cycle, and
library retrieval is MODE-SENSITIVE (a primitive can miss on a concept query yet top-rank under
`--type`/`--goal`). Before claiming absence you MUST run the LIBRARY SEARCH command in ALL THREE modes
(`"<concept>"`, `--type "<pattern>"`, `--goal "<the Lean goal>"`), plus `lean_local_search` on the obvious
names, plus a Mathlib-side search (`lean_leansearch`/`lean_loogle` — a CLI miss says nothing about
Mathlib), AND check whether a near-miss (binary/2-factor or finite-space version) composes to what you
need (iterate it, don't escalate). The reason must CITE what you searched and the closest existing decl
("needs X; searched concept/type/goal + local, found only Y, which does not compose because …"); an
escalation with no cited search is invalid.

A TOOLING FAILURE IS NOT EVIDENCE OF ABSENCE. If the CLI errors (non-zero exit, crash, no library
header, sandbox/permission error) rather than genuinely matching nothing, do NOT escalate on that basis:
fall back to `lean_local_search` and a grep of the library sources, and escalate only if those also come
up empty, noting the CLI was unavailable.
