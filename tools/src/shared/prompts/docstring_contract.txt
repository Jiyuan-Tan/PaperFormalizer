DOCSTRING CONTRACT — every public declaration carries a `/-- … -/` docstring whose FIRST paragraph is a plain-English translation of its formal statement, for an econometrician with no Lean background: no Lean syntax, no field projections, no preamble restating the signature. One or two sentences suffice; an optional second paragraph may add technical detail. Read each statement and write its docstring yourself: never generate docstrings with a script, a template or a name-to-phrase table.

Crosslinks, in that first paragraph, line the translation up with the statement row by row (the markup is invisible on the page):
- Theorem: wrap the phrase translating each hypothesis as [phrase](hyp:name) — name is the binder's name in the signature; (hyp:h1,h2) lets one phrase cover several binders — and the phrase stating the conclusion as [phrase](goal). Cover every hypothesis binder and the conclusion; a hypothesis-free theorem still links its conclusion. A data binder classified as a hypothesis (e.g. an h-named function) is linked on the phrase that introduces the object.
- Definition: wrap the phrase introducing each explicit parameter as [phrase](hyp:paramName) (a section `variable` the definition uses counts, linked by its name), the phrase naming the object defined as [phrase](goal), and, when the value is given in several clauses (a run of `let` steps, equation alternatives `| pat => …`, or conjuncts of a `def … : Prop`), the phrase for the N-th clause as [phrase](step:N) — N counts the top-level clauses, or the k clauses of a whole-value "there exist … such that (1) … (k)". An instance is annotated like a definition; an inductive links its parameters, the type as [phrase](goal), and its constructors as [phrase](hyp:ctorName) or [phrase](step:N).
- Each linked phrase states what that hypothesis, parameter or conclusion says in this statement. A placeholder that would fit any declaration ("the stated condition", "the supplied x", "the stated conclusion") is rejected.
- Write the sentence to read naturally first, then bracket the clauses. Keep brackets inside a phrase balanced; interval notation such as (0, 1/2] goes inside backticks or $…$, where brackets are ignored. Crosslinks live only in the first paragraph — no blank line between a bold title sentence and the annotated translation.
